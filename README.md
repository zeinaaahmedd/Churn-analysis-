# Customer Churn Analysis Pipeline

Welcome to the Customer Churn Analysis project! This repository contains an end-to-end Machine Learning pipeline designed to predict customer churn using both tabular demographics data and unstructured customer feedback (text).

The pipeline is fully orchestrated using **DVC (Data Version Control)** to ensure reproducibility from data preparation all the way to final report generation.

---

## 📁 Directory Structure

Here is a breakdown of what every folder and file in this repository does:

### 1. `data/`
This folder holds all the datasets used in the pipeline.
* **`raw/`**: Contains the original, un-split dataset (e.g., `telco_prep.csv`). This is the starting point of the pipeline.
* **`processed/`**: Contains the preprocessed and split tabular datasets (e.g., `X_train.csv`, `X_val.csv`, `X_test.csv`, and their corresponding `y_*.csv` label files). These are generated automatically by `src/prepare.py`.

### 2. `src/` (Source Code)
This folder contains all the Python scripts that make up the steps in our ML pipeline.
* **`inspect_data.py`**: A utility script used for exploratory data analysis (EDA). It helps quickly summarize and verify the integrity of the raw data.
* **`prepare.py`**: The first pipeline step. It reads the raw data, cleans it, handles missing values, scales numerical features, encodes categorical features, and splits it into Train, Validation, and Test sets saved to `data/processed/`.
* **`train.py`**: Trains baseline/traditional machine learning models (like Random Forest or XGBoost) strictly on the tabular data for benchmarking.
* **`train_nn.py`**: Trains the advanced **Multimodal Neural Network**. It takes both the tabular data and the raw text (`CustomerFeedback`), builds a two-branch Neural Network in Keras, trains it handling class imbalances, and saves the final model to the `models/` directory. *(See `src/train_nn_README.md` for a deep dive into this specific script).*
* **`evaluate_and_plot.py`**: Evaluates the trained Neural Network (typically on the validation set) and generates visual graphics. It outputs images like sentiment distributions and model comparison matrices into the `plots/` folder.
* **`final_test_evaluation.py`**: The final testing script. It loads the finalized model and evaluates it *only* on the completely unseen Test dataset, saving the raw metrics to `plots/final_test_metrics.csv`.
* **`generate_report.py`**: The final pipeline step. It reads the CSV metrics from the test evaluation and compiles them into a clean, readable markdown report (`FINAL_REPORT.md`).

### 3. `models/`
The destination folder for saved machine learning models. For example, `train_nn.py` saves the trained neural network here as `multimodal_nn_model.keras` so it can be loaded later for inference or evaluation.

### 4. `plots/`
The destination folder for all pipeline artifacts that are not models or datasets. This includes:
* Generated graphs/visualizations (`.png` files).
* Raw metric outputs (`.csv` files).

### 5. Root Project Files
* **`dvc.yaml`**: The heart of the DVC pipeline. It defines the exact order to run the `src/` scripts, which files each script depends on (`deps`), and which files they generate (`outs`). The stages defined here are: `prepare` -> `train` -> `train_nn` -> `visualize` -> `test_evaluation` -> `report`.
* **`dvc.lock`**: An auto-generated file by DVC that locks the exact hashes/versions of the data and code for complete reproducibility.
* **`FINAL_REPORT.md`**: The automatically generated, human-readable summary of the model's performance on the test set. (Generated by `src/generate_report.py`).
* **`.dvc/` & `.dvcignore`**: Configuration files used by the DVC tool to know how to track data and what files to ignore.
* **`.gitignore`**: Tells Git which files (like large datasets or virtual environments) to exclude from version control.

## 🚀 How to Run the Pipeline

Because the project uses DVC, you do not need to run the python scripts manually one by one. You can execute the entire pipeline from data preparation to report generation with a single command:

```bash
dvc repro
```

This command will read `dvc.yaml`, figure out what files have changed, and run only the necessary python scripts in the correct order to update the models and the `FINAL_REPORT.md`.
